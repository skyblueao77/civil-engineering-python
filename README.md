An introductory Python learning resource for students studying civil engineering, environmental engineering, and urban engineering.

This project is designed for students who are beginning to learn Python. It covers the fundamentals of using Python in civil engineering through the following progression:

**Environment Setup → Python Basics → Data Processing → Visualization → Numerical Computing → Civil Engineering Applications**

The repository is designed to be used together with the accompanying Qiita articles, Jupyter Notebooks, and Python scripts.

## Target Audience

This project is intended for:

- Civil engineering students
- Environmental engineering students
- Urban engineering students
- Students who are beginning to learn Python
- Programming beginners
- Students who want to perform data analysis in civil engineering

### Method 1: Use Google Colab

**This method is recommended if you simply want to try Python first.**

Google Colab allows you to execute Python code directly in a web browser without manually setting up a local Python environment.

You can upload or open the corresponding Jupyter Notebook and execute the code interactively.

Google Colab is recommended for people who:

- Want to try Python first
- Want to learn without setting up a local environment
- Do not want to install Python on their computer
- Want to run Jupyter Notebooks in a browser

Visit:

[Google Colab](https://colab.research.google.com/)

---

### Method 2: Use uv + PyCharm

**This method is recommended if you plan to study Python continuously or work with the repository locally.**

This project manages the Python environment for the entire repository using `uv`.

`uv` can manage Python versions, virtual environments, and project dependencies.

### 1. Install PyCharm

If you want to use PyCharm, install it from the official website.

https://www.jetbrains.com/pycharm

### 2. Install uv

Install uv according to the official documentation.

https://docs.astral.sh/uv/

After installation, check that uv is available:

```powershell
uv --version
```

If a version number is displayed, uv has been installed successfully.

### 3. Clone the Repository

If Git is installed, clone the repository:

```powershell
git clone https://github.com/skyblueao77/civil-engineering-python.git
```

Move into the repository directory:

```powershell
cd civil-engineering-python
```

### 4. Set Up the Python Environment

Run the following command from the project root:

```powershell
uv sync
```

`uv sync` creates or updates the project environment based on `pyproject.toml` and `uv.lock`.

This repository does not create a separate Python environment for each volume.

**The entire series shares one Python environment.**

### 5. Check the Python Version

Run:

```powershell
uv run python --version
```

The repository currently targets Python 3.13.

### 6. Start JupyterLab

From the project root, run:

```powershell
uv run jupyter lab
```

Alternatively, you can open `.ipynb` files directly in an IDE that supports Jupyter Notebooks.

### 7. Open a Learning Material

Choose the directory corresponding to the volume you want to study.

For example:

```text
qiita_03_pandas/
├── README.md
├── qiita_doboku_3.ipynb
└── qiita_doboku_3.py
```

You can read the README, execute the Notebook, and modify the example Python code while learning.

## Reproducibility and Dependency Management

Reproducibility is important when sharing educational code and numerical computing environments.

This repository uses the following files to manage the Python environment:

| File | Purpose |
| ---- | ------- |
| `pyproject.toml` | Defines the project and its dependencies |
| `uv.lock` | Records resolved dependency versions |
| `.python-version` | Specifies the Python version used by the project |

The project uses a single environment at the repository root rather than maintaining a separate environment for each volume.

After cloning the repository, run:

```powershell
uv sync
```

Using a lock file helps reduce unintended differences in dependency versions between development environments.

However, reproducibility does not guarantee that all dependencies are free of vulnerabilities. Users should keep their development tools and dependencies up to date and review relevant security advisories when appropriate.

## Pre-commit Checks

The repository uses `pre-commit` to automate development checks.

The configuration is stored in:

```text
.pre-commit-config.yaml
```

The development workflow may include tools such as:

- **Ruff**: Static analysis and code quality checks
- **Pytest**: Automated testing
- **nbmake**: Execution-based testing of Jupyter Notebooks

Developers can run all configured pre-commit checks manually:

```bash
uv run pre-commit run --all-files
```

These checks help identify formatting issues, syntax problems, unused code, and problems that prevent Python scripts or Jupyter Notebooks from executing correctly.

### Security Scope

This is an educational repository, not a security-critical production system.

The security features and development checks described above are intended to improve repository hygiene, dependency monitoring, reproducibility, and code quality.

They should not be interpreted as a guarantee that the repository or every dependency is completely free of vulnerabilities.

## Learning Python in the Age of AI

Generative AI can produce Python code relatively easily.

This raises a reasonable question:

> **Do I still need to learn Python if AI can generate code?**

This project does not reject AI-assisted programming.

Instead, it emphasizes the ability to:

> **Understand, verify, and modify AI-generated code.**

Even when AI generates code, engineers and students still need to consider questions such as:

- What is being calculated?
- Is the input data appropriate?
- Are physical quantities and units handled correctly?
- Why did an error occur?
- Is the numerical method appropriate?
- Is the calculated result reasonable?
- Does the result make sense from a civil engineering perspective?

In engineering applications, successful code execution alone does not demonstrate that an analysis is correct.

```text
Code runs successfully
        ≠
Engineering result is correct
```

Python knowledge therefore remains useful not only for writing programs, but also for understanding and evaluating code produced with AI assistance.

This project aims to develop both programming skills and the ability to critically verify computational results.

## Troubleshooting

### `uv` Command Not Found

Check whether uv is available:

```powershell
uv --version
```

If the command is not recognized, check the installation instructions in the official documentation:

https://docs.astral.sh/uv/

---

### The Python Version Is Different

Check the Python version used by the project:

```powershell
uv run python --version
```

The repository specifies its Python version using `.python-version` and project configuration at the repository root.

---

### A Package Cannot Be Found

First, run:

```powershell
uv sync
```

from the repository root.

Then check whether your IDE or Jupyter environment is using the Python environment associated with the project.

---

### The Python Environment Cannot Be Selected in a Notebook

If the project environment does not appear as an available Jupyter kernel, you can register it manually.

From the project root, run:

```powershell
uv run python -m ipykernel install --user --name civil-engineering-python --display-name "Python (civil-engineering-python)"
```

Then restart Jupyter or your IDE and select:

```text
Python (civil-engineering-python)
```
